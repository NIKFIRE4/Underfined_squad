Техническое задание на разработку сервиса подбора контрагентов

Сервис принимает данные закупки и возвращает ранжированный список поставщиков, производителей и дистрибьюторов. Для каждого контрагента указаны роль, статус и причины, по которым он попал в список.

1Общие сведения

НаименованиеИнтеллектуальный сервис поиска релевантных поставщиков, производителей и дистрибьюторов для АИС ГЗ и Электронного магазина Санкт-Петербурга
ПостановщикRLT, Университет Росэлторг (кейс хакатона)
ИсполнительКоманда хакатона
Сроки1–2 октября 2026, защита по итогам второго дня
Исходные данныеТри выгрузки за 2024–2025 гг.: Извещения, ТРУ, Поставщики (раздел 4)
РезультатРаботающий веб-сервис, исходный код, скрипт развёртывания, отчёт о качестве рекомендаций, презентация
Ограничение организаторов. Внешние API нейросетей использовать запрещено. Все модели (эмбеддинги, классификаторы, языковая модель, если понадобится) работают локально внутри контура сервиса. Обращения к государственным реестрам данных ограничением не считаются, но список источников согласуем с организаторами (раздел 12).

2Назначение и цели

По данным закупки сформировать ранжированный список потенциально релевантных контрагентов.

Цели сервиса:

  • сократить время, которое заказчик тратит на поиск исполнителей и анализ рынка;
  • расширить конкуренцию: показать компании, которые ещё не участвовали в закупках СПб, но способны поставить нужный товар;
  • сделать каждую рекомендацию проверяемой: роль, статус и причины выводятся из фактов с указанием источника.

3Сценарий работы заказчика с сервисом

Основной пользователь: специалист заказчика (контрактный управляющий), который готовит закупку и хочет понять, кто может её исполнить. Второстепенный: аналитик оператора площадки, который изучает конкуренцию по категориям.

  1. 1Вход. Заказчик выбирает лот по lot_id из базы или вставляет текст будущей закупки: позиции, ОКПД2 (если известен), НМЦК, признак «только МСП».
  2. 2Карточка лота. Интерфейс показывает распознанные позиции, коды ОКПД2, НМЦК, заказчика и ограничения. Здесь можно поправить код или удалить позицию.
  3. 3Разбор. Лемматизация, извлечение ключевых сущностей, предсказание ОКПД2 по тексту, если код не задан.
  4. 4Кандидаты. Три канала по истории: совпадение ОКПД2 по уровням, близость эмбеддингов к прошлым лотам, граф «похожие заказчики покупали у…».
  5. 5Открытые источники. Новые компании по ОКВЭД и реестрам производителей; реквизиты, статус МСП, финансы, РНП для всех кандидатов.
  6. 6Фильтры и обогащение. Отсев по МСП (если is_smp), ликвидации и РНП. Карточки дополняются данными из кеша реестров.
  7. 7Роль и ранжирование. Определение роли, расчёт скора 0–100 и статуса, формирование 2–3 причин.
  8. 8Выдача. Таблица топ-N: скор, роль, статус, регион, МСП, причины, отметка «новый в пуле».
  9. 9Изучение. Заказчик раскрывает карточки контрагентов: реквизиты, ОКВЭД, история закупок, финансы, источники данных.
  10. 10Решение. Подходит ли список для дальнейшей работы.
  11. 11Результат. Выгрузка в XLSX или список для приглашения к участию.
  12. 12Уточнение. Фильтры по роли, региону, МСП, «только новые»; исключение конкретных компаний. Сервис пересчитывает ранжирование.
  13. 13Отклик. Отметки «подходит / не подходит / исключить» сохраняются и используются при следующем обучении ранкера.

6Методология подбора

6.1 Каналы кандидатов

ОКПД2 по иерархии

Поставщики с тем же кодом, затем с родительскими уровнями: 32.50.13.190 → 32.50.13 → 32.50 → 32. Чем глубже совпадение, тем выше вес.

Семантическая близость

Эмбеддинги product_name и subject локальной моделью (multilingual-e5 или bge-m3), ANN-поиск похожих лотов и их участников.

Граф заказчиков

Поставщики, работавшие с этим заказчиком или с похожими: тот же тип учреждения, район, набор закупаемых кодов.

Внешние реестры

Компании без истории в СПб: ГИСП и реестр промпродукции, реестр медизделий, ГРЛС, ЕГРЮЛ по ОКВЭД, соответствующему ОКПД2.

6.3 Модель

  • Ранкер: LightGBM LambdaRank, группа = лот. Метки: 2 — победитель, 1 — участник, 0 — кандидаты из каналов, которые не участвовали.
  • Кандидаты без истории: отдельный контентный скор (ОКВЭД ↔ ОКПД2, наличие в реестре производителей, близость описания деятельности), приведённый к общей шкале 0–100.
  • Объяснение: SHAP-вклады признаков переводятся в фразы по шаблонам, в выдачу попадают 2–3 крупнейших положительных вклада.

6.4 Роли контрагентов

РольПравилаПример доказательства в карточке
ПроизводительОсновной ОКВЭД в разделе C (10–33), соответствующий ОКПД2 лота; запись в ГИСП, реестре медизделий или ГРЛС«ОКВЭД 32.50 — производство медицинских инструментов; найден в реестре промпродукции»
ДистрибьюторОКВЭД 46.xx (оптовая торговля); широкий набор разных ОКПД2 в истории; поставки нескольким типам заказчиков«ОКВЭД 46.46; поставлял 37 разных кодов класса 21»
Поставщик-исполнительОКВЭД 47.xx или сервисные разделы (33, 43, 81, 86 и др.); работает преимущественно в регионе«ОКВЭД 33.12; 12 договоров на ремонт оборудования в СПб»

У роли есть уверенность: высокая, если правила по ОКВЭД и по реестру совпали; средняя, если сработало одно правило; низкая, если роль выведена только из истории закупок.

10Оценка качества и приёмка

10.1 Офлайн-оценка

  • Сплит по времени: индексы и обучение на лотах с 08.01.2024 по 30.06.2025, тест на лотах с 01.07.2025 по 31.12.2025.
  • Цель: для каждого тестового лота реальный победитель (и участники для ЭМ) должен оказаться в топ-K выдачи.
  • Метрики: Recall@10, Recall@50, NDCG@10, MRR.
  • Срезы: ЭМ и АИС ГЗ; частые и редкие ОКПД2; МСП-закупки; новые для заказчика поставщики.
  • Бейзлайн: «самые частые победители по коду ОКПД2». Решение должно превзойти его на всех срезах.
  • Обогащение: доля кандидатов с заполненными ОКВЭД, МСП и финансами; точность роли на ручной выборке из 100 компаний.

10.3 Чек-лист приёмки

  • Стенд поднимается с нуля одной командой, данные загружаются скриптом
  • Для любого из демо-лотов выдача приходит быстрее 3 с
  • В каждой строке выдачи есть скор, роль, статус и не меньше двух причин
  • В выдаче по каждому демо-кейсу есть хотя бы одна компания со статусом «Новый в пуле»
  • Карточка контрагента показывает источник и дату каждого поля
  • Таблица метрик против бейзлайна готова для презентации
  • Ни один компонент не обращается к внешним API нейросетей

11План реализации

Четыре параллельных направления работают в пяти фазах. Переход между фазами проходит через контрольную точку (Г1–Г4). Главная точка — Г3: после неё сквозной поток работает, и остаток времени уходит на качество.

Сценарий защиты

  1. Проблема заказчика и цифры по данным: 600 тыс. лотов, длинный хвост поставщиков.
  2. Живое демо: лот медизделий → выдача → карточка производителя «Новый в пуле» → выгрузка.
  3. Ручной текст без ОКПД2 и МСП-закупка.
  4. Таблица метрик против бейзлайна, по срезам.
  5. Архитектура и масштабирование (рис. 2), соблюдение запрета на внешние нейросети.
  6. Развитие: журнал отклика, интеграция в АИС ГЗ и ЭМ.
