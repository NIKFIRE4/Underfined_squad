# Обогащение поставщиков по ИНН: рабочие рецепты для хакатона RLT (на 01.10.2026)

Главный вывод: для 44 199 ИНН за одну ночь основой должны быть **массовые выгрузки ФНС** (реестр МСП, численность, уплаченные налоги, недоимки, правонарушения). Поштучные запросы оставьте для того, чего нет в выгрузках: ГИР БО (бухотчётность) и карточка «Прозрачного бизнеса» для юрлиц не из МСП. КАД, ФССП, ГИСП и ЕИС без подготовки в одну ночь не дадут надёжных данных. Их стоит заменить флагами из ФНС и коммерческим API.

## TL;DR

- **Берём:** открытые данные ФНС (rsmp, sshr2019, paytax, debtam, taxoffence) — это ZIP с XML, качаются один раз. ГИР БО — `GET /advanced-search/organizations/search?query=<ИНН>&page=0` → `content[0].id` → `GET /nbo/organizations/{id}/bfo/`. ЕГРЮЛ и ПБ — то, что у вас уже работает. Для новых компаний по ОКВЭД и региону 78/47 выгрузка РМСП — единственный бесплатный массовый источник.
- **Запасной:** карточка ПБ (`company-proc.json`): там недоимки, ССЧР, налоги, спецрежимы и счётчики «в скольких ЮЛ руководитель». Её ограничивает капча при частых запросах, порог нигде не опубликован. Федресурс по `backend/companies?code=` с заголовком `Referer`. Реестр ПО Минцифры и ПП 719 (ГИСП) скачиваются как XLS/XML. **Не стоит** без браузерной автоматизации: КАД (cookies `wasm`/`pr_fp` выставляет JS), ЕИС (FTP закрыт с 01.01.2025, сервисы отдачи требуют регистрации через ЕСИА и токен).
- **Аккаунты:** DaData — бесплатно 10 000 запросов в день (страница цен dadata.ru: «Как «Легкий», но с лимитом 10 000 запросов в день»), не больше 30 запросов в секунду и 60 новых соединений в минуту с одного IP (документация `find-party`); на всю базу не хватит, но хватит для валидации и для ИП. Checko (тариф «Лайт» — «не более 100 запросов в сутки», checko.ru/integration/api) и ofdata (API 2.3 — «до 100 запросов в сутки») бесплатны в пределах 100 запросов в сутки. Заводить стоит только DaData (и Checko для точечных арбитражных дел), если организаторы разрешат.

### 2. ГИР БО (приоритет 1)

**Почему у вас было пусто для 7707049388.** Путь `/advanced-search/organizations/search?query=<ИНН>&page=0` правильный.\[1\]\[2\] Его используют статья на Infostart (18.12.2025) и репозитории `like-a-freedom/bfo_crawler` и `Mottorolla/company_analyst_desktop`.\[1\]\[2\]\[3\] Пустой `content` почти наверняка означает отсев «робота» по заголовкам. Автор Infostart пишет, что API проверяет заголовки и что «в большинстве случаев хватает user-agent и host», а иногда нужны cookies.\[2\] Рецепт: браузерный `User-Agent`, `Accept: application/json, text/plain, */*`, `Accept-Language: ru`, предварительный `GET /` для cookies, `Referer: https://bo.nalog.gov.ru/` (Referer — моя мера предосторожности, источником не подтверждён). Запасной путь к `id` — поле `bourl` вида `https://bo.nalog.gov.ru/organizations-card/{id}`, которое есть в выдаче ПБ (по описанию api-cloud.ru).\[4\]

**JSON-пути** (`/nbo/organizations/{id}/bfo/` возвращает массив, новые годы идут первыми; суммы в тыс. руб.):\[2\]
- выручка: `[i].typeCorrections[0].correction.financialResult.current2110` — подтверждено Infostart, 12.2025;\[2\]
- год: `[i].period`; запасное поле выручки: `[i].gainSum`;\[2\]
- чистая прибыль `...financialResult.current2400`, активы `...balance.current1600`, капитал `...balance.current1300` — **вывод по аналогии, не подтверждён**; проверьте на одном ответе, ключи могут называться иначе (например, `balance` у упрощённой отчётности).
- Прочие эндпоинты: `/nbo/organizations/{id}` (карточка), `/nbo/context` (периоды), `/download/bfo/pdf/{id}?period=YYYY&detailId=...` (PDF).\[1\]\[3\]
- Отчётность есть с 2019 года. У ИП её нет совсем — для 10% ваших ИНН ГИР БО не запрашивайте.\[3\]\[5\]

**Массовая выгрузка БФО.** Официального открытого набора с полной БФО всех организаций я не нашёл (на 01.10.2026). Есть два частичных варианта: набор ФНС `7707329152-revexp` (доходы и расходы по данным бухотчётности, только две цифры) и платная база ofdata.ru «Финансовая отчетность 2011–2025» в JSON или дампе PostgreSQL.\[6\]\[7\] Сканирование всех организаций с отчётностью за год через `/advanced-search/organizations/?allFieldsMatch=false&period=2023&page=0` (по 20 на страницу, описано tochno.st) за ночь не уложится.\[8\]

### 3. Прозрачный бизнес: полная карточка (приоритет 2)

Цепочка, описанная на Habr в 2022 году (зеркало pvsm.ru):
1. `POST /search-proc.json` → `token` организации;
2. `POST /company-proc.json token=<токен>&method=get-request` → новые `token` и `id` (здесь часто появляется капча);
3. `POST /company-proc.json token=<новый>&id=<id>&method=get-response` → JSON карточки.\[9\]

Капча: `GET /static/captcha.bin?r=<ts>&a=<hex>&version=2` → `POST /captcha-proc.json captcha=<6 цифр>` → токен в поле `pbCaptchaToken`.\[9\] Распознавание нейросетью вам запрещено, ручной ввод на 44 тыс. ИНН нереален. Поэтому карточку ПБ используйте только как дозапрос для ЮЛ, которых нет в выгрузках.

Поля карточки (имена по описанию обёртки api-cloud.ru, журнал изменений от 31.05.2026; сырые ключи pb.nalog.ru могут отличаться):
- `arrear[]` — недоимка: `year, kbk, arrearsum, penaltysum, finesum, totalsum`;
- `taxpay[]` — уплаченные налоги: `year, kbk, kbkname, taxsum`;
- `taxlist[]` — спецрежимы: `taxCode` ∈ `usn, ausn, eshn, envd, spr`;
- `employeeslist[]` — ССЧР: `year, count`;
- `masruk[]` и `masuchr[]` — руководители и учредители с `cnt` (во скольких ЮЛ участвует человек), это и есть признак «массовости» и участия в других ЮЛ;
- `invalid`, `statusORG`, `okvedList[]`, `dateReg`.\[4\]

По описанию parser-api.com, в карточке есть ещё флаги «задолженность свыше 1000 ₽ передана приставам» (`has_bailiff_debt`) и «не сдаёт отчётность более года» (`has_no_reporting`).\[10\] Это лучшая бесплатная замена ФССП.

Порог капчи нигде не опубликован. Обёртки ставят таймаут 120 с и делают ретраи.\[4\] Практическая рекомендация: не больше 1 запроса в 2–3 с с одного IP, при появлении капчи — пауза 10–15 минут (это эвристика, она не подтверждена).

## Details: сниппеты для «берём»

### Общий клиент (троттлинг, ретраи, source + fetched_at)
```python
import asyncio, random, datetime as dt, httpx
UA = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/128.0 Safari/537.36"

class Src:
    def __init__(self, base, rps, headers=None):
        self.c = httpx.AsyncClient(base_url=base, timeout=60, follow_redirects=True,
                                   headers={"User-Agent": UA, "Accept-Language": "ru", **(headers or {})},
                                   http2=False)
        self.gap, self.lock, self.last = 1/rps, asyncio.Lock(), 0.0
    async def req(self, method, url, **kw):
        for attempt in range(5):
            async with self.lock:
                wait = self.last + self.gap - asyncio.get_event_loop().time()
                if wait > 0: await asyncio.sleep(wait)
                self.last = asyncio.get_event_loop().time()
            try:
                r = await self.c.request(method, url, **kw)
                if r.status_code in (429, 500, 502, 503, 504): raise httpx.HTTPStatusError("retry", request=r.request, response=r)
                return r, dt.datetime.now(dt.timezone.utc)   # fetched_at
            except (httpx.TransportError, httpx.HTTPStatusError):
                await asyncio.sleep(2**attempt + random.random())
        raise RuntimeError(f"failed {url}")
```
Сохраняйте сырой JSON в таблицу `raw_fetch(inn, source, url, fetched_at, status, body jsonb)`, а нормализованные поля — с колонками `source` и `fetched_at`. Повторный прогон должен идти из кэша.

### ГИР БО
```python
bo = Src("https://bo.nalog.gov.ru", rps=2, headers={"Accept": "application/json, text/plain, */*",
                                                    "Referer": "https://bo.nalog.gov.ru/"})
async def bfo(inn):
    await bo.req("GET", "/")                                   # cookies
    r, ts = await bo.req("GET", "/advanced-search/organizations/search", params={"query": inn, "page": 0})
    content = r.json().get("content") or []
    if not content: return None
    oid = content[0]["id"]
    r, ts = await bo.req("GET", f"/nbo/organizations/{oid}/bfo/")
    out = []
    for y in r.json():
        c = (y.get("typeCorrections") or [{}])[0].get("correction", {})
        fr, bl = c.get("financialResult", {}), c.get("balance", {})
        out.append({"year": y.get("period"), "rev_2110": fr.get("current2110"),
                    "np_2400": fr.get("current2400"), "eq_1300": bl.get("current1300"),
                    "assets_1600": bl.get("current1600"), "source": "bo.nalog.gov.ru", "fetched_at": ts})
    return out
# Пример (сокращённо): [{"year":"2024","rev_2110":..., "np_2400":..., ...}, ...]  (тыс. руб.)
```

## Таблица признаков добросовестности

| Признак | Открытый источник | Интерпретация |
|---|---|---|
| Недостоверность сведений (`invalid`) | ПБ, ЕГРЮЛ | сильный красный флаг |
| Статус ликвидации или реорганизации | ПБ, ЕГРЮЛ | исключать или резко понижать |
| Возраст компании (`dateReg`) | ЕГРЮЛ | младше 1 года — риск |
| Массовый адрес | ФНС `masaddress`, поиск ПБ по адресу | риск номинальности |
| Массовый руководитель или учредитель (`cnt`) | ФНС `massleaders`, `masruk/masuchr` в ПБ | риск номинальности |
| Дисквалификация руководителя | `service.nalog.ru/disqualified.do` | красный флаг |
| Недоимки, пени, штрафы | ФНС `debtam`, `arrear` в ПБ | учитывать сумму относительно выручки |
| Налоговые правонарушения | ФНС `taxoffence` | умеренный риск |
| Не сдаёт отчётность больше года | флаг ПБ | сильный красный флаг |
| Долг у приставов > 1000 ₽ | флаг ПБ | риск |
| ССЧР = 0–1 | `sshr2019`, РМСП | признак «пустышки»; для исполнителя — недостаток ресурсов |
| Уплаченные налоги ≈ 0 при большой выручке | `paytax` + ГИР БО | риск фирмы-однодневки |
| Отрицательный капитал (1300), убытки (2400) | ГИР БО | финансовая неустойчивость |
| Банкротство или намерение | Федресурс | исключать |
| РНП | ЕИС | исключать (сейчас недоступно без токена) |
| Арбитраж как ответчик | КАД (платные API) | учитывать долю исков к выручке |
| Реестр ПП 719, реестр ПО, медизделия | ГИСП, Минцифры, Росздравнадзор | плюс к роли «производитель» |

Методики индекса должной осмотрительности СПАРК и скоринга Контур.Фокуса в этой сессии не исследовались. Перечень выше составлен по признакам, которые эти сервисы публично показывают в карточках. Почти все признаки берутся из перечисленных открытых источников ФНС.

## Recommendations: план на ночь

1. **Сейчас (≈1 ч):** скачать rsmp, sshr2019, paytax, debtam, taxoffence; разобрать в таблицы `fns_*` с `source = URL набора` и `fetched_at`. Это закрывает ≈80% признаков для большинства ИНН без единого поштучного запроса.
2. **Ночью:** ГИР БО для ≈40 тыс. юрлиц — 2 запроса на ИНН. При 2 запросах в секунду это ≈11 ч. Если не успевает — 2–3 IP или приоритет ИНН из СПб.
3. **ПБ-карточка** только для юрлиц не из МСП и без данных в выгрузках; при капче — пауза.
4. **Федресурс** только для топ-N итогового рейтинга.
5. **Ручная загрузка:** XLSX ПП 719 из ГИСП и экспорт реестра ПО.

## Риски и подводные камни

- `bo.nalog.ru` → `bo.nalog.gov.ru` (переезд домена); JSON-эндпоинты недокументированы и могут смениться без предупреждения (README Mottorolla прямо называет признак смены — 404/400 на все ИНН).\[3\]
- ЕИС: FTP закрыт 01.01.2025, доступ только по ЕСИА-токену; HTTPS — только с корневым сертификатом Минцифры.
- ПБ: капча при частых запросах; распознавание нейросетью вам запрещено правилами.
- `file.nalog.ru` медленный; структура XSD меняется (rsmp: `structure-10062025` → `structure-12052026` с релиза 10.06.2026) — парсер должен опираться на XSD текущего релиза.\[11\]
- Набор дисквалифицированных заморожен с 2021 года — не используйте его как актуальный.\[17\]
- РМСП: ССЧР с запаздыванием (по правилам набора), крупных компаний нет.\[11\]
- КАД: антибот на WASM, ответы 403/451.

## Caveats

- Имена полей карточки ПБ взяты из коммерческих обёрток (api-cloud.ru, parser-api.com), а не из сырого ответа: проверьте на одном ИНН.\[4\]\[10\]
- Ключи `current2400`, `current1300`, `current1600` в ГИР БО выведены по аналогии с подтверждённым `current2110`.
- Размеры выгрузок, наличие ИНН в экспорте реестра ПО, ГРЛС и ФССП не проверены.
- Лимит ЕИС 5000 запросов в час относился к временному сервису без регистрации, а текущая инструкция для getDocsIP точной цифры не даёт; данные vaskov.pro — сторонние, не официальные.
