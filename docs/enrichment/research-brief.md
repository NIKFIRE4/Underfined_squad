# Бриф на исследование: источники данных о компаниях по ИНН

## Контекст

Мы участвуем в хакатоне RLT (Университет Росэлторг, Санкт-Петербург, 1–2 октября 2026). Строим сервис, который по данным госзакупки (44-ФЗ, площадки АИС ГЗ и Электронный магазин СПб) выдаёт ранжированный список поставщиков, производителей и дистрибьюторов.

Моя часть — **парсер обогащения**: по ИНН собрать о компании всё, что помогает:
1. показать её карточку;
2. оценить её добросовестность;
3. определить её роль: производитель, дистрибьютор или исполнитель;
4. найти **новые** компании по ОКВЭД и региону, которых нет в нашей исторической выгрузке.

Данные пишем в PostgreSQL. У каждого поля обязательно хранятся источник и дата получения.

## Ограничения

- **Внешние API нейросетей запрещены.** Обращения к государственным реестрам разрешены.
- Коммерческие API данных (DaData, Checko и т.п.) — под вопросом у организаторов. Их тоже исследуй, но отдельным блоком.
- Объём: **44 199 уникальных ИНН** (около 90% — юрлица, остальные ИП, 53% из Санкт-Петербурга). Пакетный прогон должен уложиться примерно в одну ночь. Поэтому критичны лимиты частоты, капча и **массовые выгрузки** (bulk dumps).
- Стек: Python 3.12, `httpx`. Запросы идут из РФ.
- Время — часы, а не дни. Нужны рабочие рецепты, а не обзор рынка.

## Уже проверено (2026-10-01) — повторно не исследовать, только уточнять

- `egrul.nalog.ru`: `POST / query=<inn>` → `t`, `GET /search-result/<t>`. JSON без капчи: ОГРН, КПП, имя, руководитель, дата регистрации, регион.
- `pb.nalog.ru`: `POST /search-proc.json mode=search-ul&queryUl=<inn>` → `id`, `POST id=<id>&method=get-response`. JSON: статус, основной ОКВЭД, признак недостоверности (`invalid`), признак ликвидации, токен карточки.
- `rmsp.nalog.ru`: `POST /search-proc.json query=<inn>`. JSON работает.
- `bo.nalog.ru` редиректит на `bo.nalog.gov.ru`. `GET /advanced-search/organizations/search?query=<inn>&page=0` отдаёт JSON, но **для 7707049388 пусто** — параметры неверные.
- `zakupki.gov.ru`: работает только с сертификатом Минцифры (без проверки TLS отдаёт 200 HTML).
- `gisp.gov.ru` → 403, `fedresurs.ru` → 401, `kad.arbitr.ru` открывается, но есть защита от ботов, `file.nalog.ru/opendata` не ответил за 10 секунд.

## Что исследовать

Для каждого источника нужны:
- точный эндпоинт, метод и параметры;
- формат ответа и список полей;
- лимиты частоты;
- нужны ли капча, cookies, сессия, особые заголовки или регистрация;
- есть ли массовая выгрузка или открытые данные (URL, формат, размер, частота обновления);
- **рабочий пример** на `curl` или Python;
- вердикт: «берём», «запасной» или «не стоит».

Приоритет сверху вниз:

1. **ГИР БО (bo.nalog.gov.ru):** правильный поиск по ИНН и получение бухотчётности по годам (выручка — строка 2110, чистая прибыль — 2400, капитал — 1300, активы — 1600). Есть ли массовая выгрузка БФО в открытых данных ФНС.
2. **Прозрачный бизнес, полная карточка** (`company-proc.json` или аналог по токену): какие поля есть — недоимки, численность, налоги, спецрежим, массовый адрес или руководитель, дисквалификация, участие в других ЮЛ. Лимиты, когда появляется капча.
3. **Открытые данные ФНС** (nalog.gov.ru/opendata): актуальные URL наборов — реестр МСП (с ОКВЭД), численность сотрудников, уплаченные налоги, недоимки и пени, спецрежимы, доходы и расходы, дисквалифицированные лица, массовые адреса. Размер, формат, дата обновления, зеркала, если file.nalog.ru недоступен.
4. **ЕИС (zakupki.gov.ru):**
   - РНП по ИНН: HTML-поиск, открытые данные ЕИС, FTP `ftp.zakupki.gov.ru` или новый способ;
   - реестр контрактов по поставщику (история вне СПб);
   - ЕРУЗ (реестр участников закупок).
   - Как подключить сертификат Минцифры в Python.
5. **Федресурс:** банкротства и сообщения о компании по ИНН — эндпоинты `fedresurs.ru/backend/...`, нужные заголовки.
6. **Источники для роли «производитель»:**
   - ГИСП (реестр промышленной продукции по ПП 719, реестр российской продукции);
   - реестр медизделий Росздравнадзора (производители, поиск по ИНН, открытые данные);
   - ГРЛС (держатели регистрационных удостоверений);
   - реестр российского ПО Минцифры (правообладатели, ОКПД2 58).
   - Для каждого: выгрузка или API, можно ли искать по ИНН.
7. **Новые компании по ОКВЭД и региону:** какой бесплатный источник позволяет получить список компаний по ОКВЭД (и региону 78/47) — расширенный поиск ПБ, выгрузка РМСП, другое. Нужно, чтобы находить поставщиков, которых нет в истории закупок.
8. **Соответствие ОКПД2 ↔ ОКВЭД2:** есть ли официальная или общепринятая таблица соответствия, где её взять машиночитаемой.
9. **КАД арбитр и ФССП:** реально ли получить арбитражные дела (компания как ответчик) и исполнительные производства без капчи. Если нет — альтернативы.
10. **Коммерческие API (отдельный блок):** DaData (`findById/party`), Checko, ofdata.ru, api-fns.ru, «За честный бизнес». Для каждого: бесплатный лимит, какие поля даёт бесплатно, нужна ли регистрация юрлица. Решаем, стоит ли заводить аккаунты.

Отдельно: **какие признаки добросовестности используют коммерческие сервисы проверки контрагентов** (индекс должной осмотрительности СПАРК, скоринг Контур.Фокус, Checko) и из какого **открытого** источника берётся каждый. Это нужно, чтобы собрать максимум признаков для нашего ранкера.

## Формат результата

1. **Сводная таблица:** источник → поля → доступ (API, HTML, выгрузка) → лимиты и защита → вердикт.
2. **По каждому источнику с вердиктом «берём»:** готовый к запуску сниппет на Python (`httpx`) с примером ответа (можно сокращённого).
3. **Список массовых выгрузок** с прямыми URL и размерами.
4. **Таблица признаков добросовестности:** признак → открытый источник → как интерпретировать.
5. **Риски и подводные камни:** баны, капча, смена API в 2025–2026 годах.
6. **Список аккаунтов**, которые стоит зарегистрировать: сайт, что даёт, сколько стоит, нужен ли ИНН или телефон РФ.

Указывай дату актуальности каждого факта: API госсайтов часто меняются.
