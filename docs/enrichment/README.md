## Зачем это

По ИНН собираем данные о компании из открытых госреестров и пишем их в БД. Эти данные нужны трём потребителям:

| Потребитель | Что берёт | Требование ТЗ |
|---|---|---|
| Ранкер (Data/ML) | плоская витрина признаков `companies` | 6.2 «Компания»: регион, МСП, возраст, выручка, численность, роль |
| Фильтры и статусы | статус, РНП, МСП, финансовые флаги | ФТ-08; 6.5 «Требует проверки» |
| Карточка контрагента (UI) | поля с источником и датой | ФТ-07, ФТ-13, НФТ «Достоверность» |

Плюс поиск **новых компаний** по ОКВЭД, которых нет в выгрузке (ФТ-06, статус «Новый в пуле»).
Это блок «Обогащение и расширение пула» — 25 баллов из 100.

## Инварианты (не нарушать)

1. **У каждого обогащённого поля есть `source` и `fetched_at`.** Это прямое требование ТЗ. Значение без источника в БД не пишем.
2. **Никаких внешних API нейросетей** (запрет организаторов). Госреестры разрешены. Коммерческие API (DaData, Checko и т.п.) — только после ответа организаторов, см. «Открытые вопросы».
3. **Недоступность источника не ломает выдачу.** Карточка помечается «не обогащено», запрос повторяется в фоне.
4. **Сырые ответы сохраняем** (`raw_responses`), чтобы перепарсить без повторного похода в сеть.
5. **Лимиты частоты соблюдаем** на уровне клиента каждого источника: нас не должны забанить посреди демо.
6. ИНН валидируем по контрольной сумме до запроса: 10 знаков — юрлицо, 12 — ИП.

## Стратегия

- **Пакетный прогон заранее.** В выгрузке 44 199 уникальных ИНН. Обогащаем их все в фоне до демо, а не при запросе пользователя.
- **Массовые признаки из открытых выгрузок ФНС**, если их удастся скачать: все 44 тыс. ИНН за минуты, без лимитов. Реестр МСП содержит ОКВЭД всех малых компаний, поэтому служит и источником новых компаний.
- **Скрапер на запрос** — для свежей карточки и для компаний не из выгрузки.

## Модель данных (черновик, согласуем с бэкендом)

```sql
-- сырые ответы, по ним можно перепарсить
raw_responses(id, inn, source, request_key, status_code, body jsonb|text, fetched_at)

-- нормализованные факты: «источник и дата у каждого поля»
company_facts(inn, field, value jsonb, source, fetched_at, PRIMARY KEY (inn, field, source))

-- плоская витрина для ранкера и UI, пересобирается из company_facts
companies(inn PK, ogrn, kpp, name, short_name, kind /*ul|ip*/, region_code,
          status, reg_date, liquidation_date, age_years,
          okved_main, okved_extra text[], charter_capital,
          smp_category, employees, revenue_last, revenue_prev, net_profit, equity,
          tax_arrears, taxes_paid, tax_regime,
          is_invalid_info, is_mass_address, is_mass_director, is_disqualified,
          in_rnp, is_bankrupt, in_gisp,
          enrichment_status /*full|partial|pending|failed*/, updated_at)
```

Значения `field` в `company_facts` совпадают с колонками `companies`.

## Стек

Python 3.12, `httpx` (async), отдельный лимитер частоты на источник, `tenacity` для повторов, PostgreSQL. Для очереди — Redis + RQ (как в ТЗ, раздел 7).
Код будет лежать в `enrichment/`: на каждый источник отдельный клиент с единым интерфейсом `fetch(inn) -> list[Fact]`.
