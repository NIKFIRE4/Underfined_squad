# Новые контрагенты в локальной PostgreSQL

Этот импорт работает с выбранной локальной базой PostgreSQL. Он не использует Docker-конфигурацию или хранилище модуля обогащения.

ИНН, ОГРН и коды сохраняются как текст. Поиск поддерживает индекс `(okpd2_group, tier, priority DESC)`, история — индекс по `supplier_inn`.

## Архив данных

[new_counterparties_pg.zip](new_counterparties_pg.zip) хранится в Git LFS. После клонирования выполните git lfs pull, чтобы получить настоящий архив вместо файла-указателя. Архив содержит четыре CSV и исходное описание датасета.

## Загрузка

Нужен Python 3.10+ и драйвер PostgreSQL:

```powershell
py -3 -m pip install -r database/new_counterparties/requirements.txt
$env:PGHOST = 'localhost'
$env:PGPORT = '5432'
$env:PGDATABASE = 'rlt'
$env:PGUSER = 'postgres'
```

Для пароля используйте локальный файл libpq `%APPDATA%\postgresql\pgpass.conf` либо переменную `PGPASSWORD`. Также поддерживается `DATABASE_URL`; не сохраняйте пароль или строку подключения в Git. Если DATABASE_URL задан, его параметры имеют приоритет над переменными PG*.

Из корня репозитория:

```powershell
py -3 database/new_counterparties/import_data.py --archive "database/new_counterparties/new_counterparties_pg.zip" --report "import-report.json"
```

Скрипт читает CSV непосредственно из ZIP/GZIP, без распаковки 1,25 ГБ файлов на диск. SQL берётся из проверенного `schema.sql` рядом со скриптом; команды из архива не запускаются.

Все четыре таблицы создаются в `public` одной транзакцией. Если таблицы или одноимённые индексы уже существуют, импорт останавливается. Ничего не удаляется и не перезаписывается. Заголовки CSV и количества строк проверяются; первичные и внешние ключи проверяют уникальность и ссылки. Затем создаются индексы и собирается статистика ANALYZE. При ошибке до фиксации вся новая загрузка откатывается.

Не запускайте `schema.sql` отдельно перед импортом: таблицы создаёт сам скрипт. Повторный запуск на уже загруженной базе не нужен.

## Проверка существующей загрузки

```powershell
py -3 database/new_counterparties/import_data.py --verify-only
```

Проверка выполняется в режиме только чтения: количества строк, первичные и внешние ключи, наличие действующих поисковых индексов.
