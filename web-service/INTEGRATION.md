# Контракт подключения модулей

## Последовательность

```text
Два CSV → проверка и связка lot_id → Lot
→ recommender.recommend(lot, top_k)
→ enricher.enrich(lot, candidates)
→ проверка контракта → сортировка score DESC → top_k → Поставщики.csv
```

Модули импортируются при запуске. Веса модели, справочники и индекс истории загружайте один раз, а не для каждого лота. После изменения кода перезапустите сервер. Веб-часть менять не нужно.

## Команда обогащения

Реализуйте `integrations/enricher.py`:

```python
from models import Candidate, Lot

READY = True

def enrich(lot: Lot, candidates: list[Candidate]) -> list[Candidate]:
    # 1. Поиск новых компаний по предмету/ОКПД2; можно дописать кандидатов.
    # 2. Реквизиты, регион, МСП, статус, роль и причины.
    # 3. Бизнес-фильтры по ограничениям закупки, РНП и действующему статусу.
    # 4. Источник + дата для проверяемых фактов.
    # 5. Согласование score новых компаний со шкалой модели.
    return candidates  # заменить реализацией команды
```

Добавленные кандидаты должны иметь заполненный ИНН, имя, скор и объяснение. Сортировку и обрезание общего списка выполнит сервер. Ограничения `is_smp` сейчас передаются как исходная строка, например `true`/`false`: нормализуйте её в модуле. Сервер не придумывает соответствие МСП и не делает заключение по РНП.

Если `enrich` выбрасывает исключение, сохраняются кандидаты модели с пометкой «Источник недоступен — требуется проверка», а задача получает предупреждение. Статус кандидата понижается до «Требует проверки». Такие строки не подтверждают соответствие ограничениям закупки. Если невозможность проверки должна исключать кандидата, обработайте её внутри адаптера и верните только допустимых кандидатов. Ошибка формата возвращённых данных останавливает задачу; она не скрывается как недоступность источника.

Сетевые таймауты, повторные попытки, кеш, нормализация ИНН с контрольной суммой и бизнес-фильтры относятся к адаптеру. На уровне сервера нет принудительного таймаута Python-функции: не допускайте бесконечных ожиданий. Внешние API нейросетей не используйте.

## Candidate

| Поле | Тип / смысл |
|---|---|
| supplier_name | `str`, название |
| supplier_inn | `str`, 10 или 12 цифр в live; проверка контрольной суммы — в адаптере |
| supplier_kpp | `str`, может быть пустым |
| score | `float`, конечное число 0–100 |
| role | `str`, производитель / дистрибьютор / поставщик-исполнитель / не определена |
| status | `str`, обоснованный статус |
| region | `str` |
| is_smp | `bool` или `None`, неизвестное не равно «нет» |
| is_new | `bool`, новый в пуле |
| reasons | `list[str]`, желательно 2–3 фактические причины |
| sources | список объектов `{field, source, url, checked_at}` |
| enrichment_status | `str`, например «Обогащено», «Не обогащено» |

`checked_at` — ISO 8601 с часовым поясом. `url` — действительный адрес источника HTTP(S). UI выводит факт, источник и дату, не выполняет HTML из полей. Сервер проверяет типы, диапазон скора и форму ИНН, удаляет повторы по ИНН. Достоверность фактов и бизнес-корректность оценок обеспечивают модули команды.

Выходные поля: `lot_id;subject;rank;supplier_name;supplier_inn;supplier_kpp;score;role;status;region;is_smp;is_new;reasons;sources;enrichment_status;is_demo`. В CSV `reasons` соединены через ` | `, `sources` — JSON, `is_smp=None` — пустая ячейка. В API предпросмотра эти поля остаются списками/объектами и `null`.

## HTTP API интерфейса

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | режим, готовность адаптеров, лимит файла |
| POST | `/api/jobs` | создать загрузку, JSON `{"top_k":10}`; ответ 201 с `id` |
| PUT | `/api/jobs/{id}/files/notices` | тело — байты CSV извещений |
| PUT | `/api/jobs/{id}/files/items` | тело — байты CSV ТРУ |
| POST | `/api/jobs/{id}/start` | запуск после двух загрузок; ответ 202 |
| GET | `/api/jobs/{id}` | статус, прогресс, счётчики, предупреждения, до 100 строк результата |
| GET | `/api/jobs/{id}/download` | готовый CSV; до завершения — 409 |

При PUT передавайте `Content-Length`, `Content-Type: text/csv` и `X-Filename` (URL-encoded имя с расширением .csv). Само имя не используется как путь хранения. Оба файла обязательно принадлежат одной задаче; нельзя перезаписать уже загруженный файл. Создавайте новую задачу для повторной загрузки.

Статусы: `uploading → queued → processing → completed | failed`.
Ошибки API: JSON `{"error":"текст"}`. Ошибка обработки: HTTP 200 при чтении задачи, `status="failed"` и поле `message`. Общий прогресс обработки начинается после отдельного прогресса загрузки, это две разные операции. Нет выдачи промежуточных частичных результатов и нет автоматического возобновления после остановки процесса.
