# Контракт подключения модулей

Отдельный endpoint для JSON-вызова уже запущенной модели: [POST /analyze](ANALYZE.md). Описанные ниже Python-адаптеры относятся к существующей цепочке обработки CSV.

## Последовательность

```text
Два CSV → проверка и связка lot_id → Lot
→ recommender.recommend(lot, top_k)
→ enricher.enrich(lot, candidates)
→ проверка контракта → сортировка score DESC → top_k → Поставщики.csv
```

Модули импортируются при запуске. Веса модели, справочники и индекс истории загружайте один раз, а не для каждого лота. После изменения кода перезапустите сервер. Веб-часть менять не нужно.

## Команда обогащения

**Подключено.** `integrations/enricher.py` вызывает `POST /api/suppliers/batch` с `offline: true` (только из базы, миллисекунды: недоступный источник вроде капчи ФНС не держит лот; `ENRICH_PIPELINE_LIVE=1` — опрашивать вживую) сервиса обогащения (`ENRICH_API_URL`, по умолчанию http://127.0.0.1:8010; пустая строка отключает) и подставляет название, КПП, регион, МСП, роль, источники полей. Исключает ликвидированных, записи РНП и не-МСП в закупках только для МСП; при флагах риска или неподтверждённом статусе ЕГРЮЛ ставит «Требует проверки». Таймаут запроса — `ENRICH_API_TIMEOUT` (60 с). Карточка (`/api/suppliers/{inn}/card`) недостающие источники опрашивает вживую, не дольше `ENRICH_API_SOURCE_TIMEOUT` на источник (в `.env` стенда — 5 с). Новые компании («Непроверенные») ищет `integrations/new_pool.py` в пуле `data/external/new_counterparties*.parquet` (`NEW_POOL_DIR`): компании, у которых группа ОКПД2 позиции лота среди их групп. Порядок — сила доказательства по этой группе (госконтракты в группе, реестр производителей или лицензия, основной ОКВЭД равен группе) сначала из СПб и ЛО, затем из других регионов, затем только ассоциация по ОКВЭД; при нескольких группах выше основная группа лота; внутри — приоритет пула. В закупке только для МСП — только МСП. Score не выше 75, статус «Новый в пуле». Пул грузится при старте сервера (~8 с, ~300 МБ), поиск по лоту — миллисекунды; без файлов пула вкладка пуста, подбор моделью работает. Недоступность сервиса обогащения не отменяет поиск новых компаний.

Контракт адаптера:

```python
from models import Candidate, Lot

READY = True

def enrich(lot: Lot, candidates: list[Candidate]) -> list[Candidate]:
    # 1. Поиск новых компаний по предмету/ОКПД2; можно дописать кандидатов.
    # 2. Реквизиты, регион, МСП, статус, роль и причины.
    # 3. Бизнес-фильтры по ограничениям закупки, РНП и действующему статусу.
    # 4. Источник + дата для проверяемых фактов.
    # 5. Согласование score новых компаний со шкалой модели.
    return candidates  # заменить реализацией команды
```

Добавленные кандидаты должны иметь заполненный ИНН, имя, скор и объяснение. Сортировку и обрезание общего списка выполнит сервер. Ограничения `is_smp` сейчас передаются как исходная строка, например `true`/`false`: нормализуйте её в модуле. Сервер не придумывает соответствие МСП и не делает заключение по РНП.

Если `enrich` выбрасывает исключение, сохраняются кандидаты модели с пометкой «Источник недоступен — требуется проверка», а задача получает предупреждение. Статус кандидата понижается до «Требует проверки». Такие строки не подтверждают соответствие ограничениям закупки. Если невозможность проверки должна исключать кандидата, обработайте её внутри адаптера и верните только допустимых кандидатов. Ошибка формата возвращённых данных останавливает задачу; она не скрывается как недоступность источника.

Сетевые таймауты, повторные попытки, кеш, нормализация ИНН с контрольной суммой и бизнес-фильтры относятся к адаптеру. На уровне сервера нет принудительного таймаута Python-функции: не допускайте бесконечных ожиданий. Внешние API нейросетей не используйте.

## Candidate

| Поле | Тип / смысл |
|---|---|
| supplier_name | `str`, название |
| supplier_inn | `str`, 10 или 12 цифр в live; проверка контрольной суммы — в адаптере |
| supplier_kpp | `str`, может быть пустым |
| score | `float`, конечное число 0–100 |
| role | `str`, производитель / дистрибьютор / поставщик-исполнитель / не определена |
| status | `str`, обоснованный статус |
| region | `str` |
| is_smp | `bool` или `None`, неизвестное не равно «нет» |
| is_new | `bool`, новый в пуле |
| reasons | `list[str]`, желательно 2–3 фактические причины |
| sources | список объектов `{field, source, url, checked_at}` |
| enrichment_status | `str`, например «Обогащено», «Не обогащено» |

`checked_at` — ISO 8601 с часовым поясом. `url` — действительный адрес источника HTTP(S). UI выводит факт, источник и дату, не выполняет HTML из полей. Сервер проверяет типы, диапазон скора и форму ИНН, удаляет повторы по ИНН. Достоверность фактов и бизнес-корректность оценок обеспечивают модули команды.

Выходные поля: `lot_id;subject;rank;supplier_name;supplier_inn;supplier_kpp;score;role;status;region;is_smp;is_new;reasons;sources;enrichment_status;is_demo`. В CSV `reasons` соединены через ` | `, `sources` — JSON, `is_smp=None` — пустая ячейка. В API предпросмотра эти поля остаются списками/объектами и `null`.

## HTTP API интерфейса

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | режим, готовность адаптеров, лимит файла |
| POST | `/api/jobs` | создать загрузку, JSON `{"top_k":10}`; ответ 201 с `id` |
| PUT | `/api/jobs/{id}/files/auto` | тело — байты CSV или .xlsx; тип таблиц сервер определит по столбцам (так загружает интерфейс) |
| PUT | `/api/jobs/{id}/files/notices` | тело — байты CSV извещений (явный тип) |
| PUT | `/api/jobs/{id}/files/items` | тело — байты CSV ТРУ (явный тип) |
| POST | `/api/jobs/{id}/start` | запуск после загрузки; ответ 202 |
| GET | `/api/jobs/{id}` | статус, прогресс, счётчики (`verified`, `unverified`), предупреждения, до 100 строк результата, `detected` — какие файлы/листы распознаны |
| GET | `/api/jobs/{id}/lots?offset=0&limit=50&q=` | результат по лотам для интерфейса: позиции ТРУ и два списка — `verified`, `unverified`; `q` ищет по лоту, предмету, названию и ИНН |
| GET | `/api/jobs/{id}/download` | готовый CSV; до завершения — 409 |
| GET | `/api/suppliers/{inn}/card` | карточка компании для интерфейса: прокси к `GET /api/suppliers/{inn}` сервиса обогащения (`enrichment/api.py`, Swagger — http://localhost:8010/docs); `?refresh=true` перезапрашивает источники; ошибки 400/404 передаются как есть, недоступность сервиса — 502, не подключён — 503 |
| GET | `/api/suppliers/{inn}/stats` | статистика поставщика; **пока заглушка** `{"available": false}`, интерфейс её больше не вызывает, контракт ниже |

В одной задаче используется один способ: либо `auto` (до 4 файлов), либо пара `notices` + `items`. При PUT передавайте `Content-Length`, `X-Filename` (URL-encoded имя с расширением .csv, для `auto` — также .xlsx). Само имя не используется как путь хранения. Оба файла обязательно принадлежат одной задаче; нельзя перезаписать уже загруженный файл. Создавайте новую задачу для повторной загрузки.

Статусы: `uploading → queued → processing → completed | failed`.
Ошибки API: JSON `{"error":"текст"}`. Ошибка обработки: HTTP 200 при чтении задачи, `status="failed"` и поле `message`. Общий прогресс обработки начинается после отдельного прогресса загрузки, это две разные операции. Нет выдачи промежуточных частичных результатов и нет автоматического возобновления после остановки процесса.

## Статистика поставщика: `GET /api/suppliers/{inn}/stats`

Карточка поставщика в интерфейсе запрашивает этот endpoint при открытии. Сейчас сервер отвечает `{"inn": "…", "available": false}`, и интерфейс показывает заглушку. Когда сервис статистики будет готов, замените заглушку в `server.py` ответом такого вида — все поля необязательны:

```json
{
  "inn": "7806410527",
  "updated_at": "2026-10-01",
  "metrics": {
    "wins": 35,
    "participations": 120,
    "win_rate": 0.29,
    "contracts_sum": 12500000,
    "customers": 18,
    "avg_discount": 0.12,
    "last_win_date": "2025-12-10",
    "years_active": 6
  },
  "top_okpd2": [{"code": "10.61.32.113", "title": "Крупа гречневая", "wins": 12}],
  "recent_wins": [{"date": "2025-12-10", "subject": "Поставка крупы", "customer": "ГБОУ школа № 1", "price": 250000}]
}
```

`win_rate` и `avg_discount` — доли 0–1, `contracts_sum` и `price` — рубли, даты — ISO 8601. Неизвестные ключи в `metrics` тоже выводятся: подпись — имя ключа. `"available": false`, `404` или `501` интерфейс считает «статистика ещё не подключена», остальные ошибки — сбоем загрузки.
